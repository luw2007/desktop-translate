### 2026-10-16 pi 输入方式、模型来源与绘制计数（源码已改，未构建未运行）

以下为 2026-10-16 源码级设计，除逐文件 `swiftc -parse` 外未经构建、类型检查或运行验证，不是验收证据，也不改变上文任何未通过门槛。

- **输入方式显式选择**：pi 模式新增 `translation.inputMode`，取值为 `ocr-text`（默认，旧配置无该键时按此解释）或 `image`。截图模式是用户显式选择，不是 OCR 失败时的自动回退或改进，也不存在模式/模型回退；设置界面在选择处显示该模式的发送内容与风险，并在捕获前可见。
- **截图模式的隐私与传输边界**：每次翻译捕获与 OCR 路径相同的精确锁定窗口/选区裁剪，编码为内存 PNG 后经 stdin 作为一条图像内容发送；不写临时文件、不入日志/错误、不放进进程参数、随会话丢弃。因此“只发送正文、不上传截图”只对默认 OCR 文字模式成立，不适用于显式选择的截图模式；截图模式会发送该裁剪内可见的一切，包括模型不需要或用户未预期的内容。
- **模型来源与能力**：模型下拉由 pi 自身 `get_available_models` 填充（只读取该命令，不发起模型请求），显示 `provider/id` 与是否声明图像输入；已保存但当前不可用的模型保持可见并标注，不被静默替换；截图模式只列出声明支持图像输入的模型，并在所选模型不可用或非图像模型时拒绝保存/发送。pi 声明支持图像输入不等于远端部署一定遵守该声明。
- **截图模式的位置证据边界**：位置由模型自报，是相对该裁剪的比例，映射回窗口本地坐标；不是原生或 OCR 验证过的几何，也没有 OCR 校准，因此对模型未识别或未报出的图标、非文字内容与文字没有任何保证，不为其生成译文或位置，也不代表定位精度达标。区域必须落在裁剪内、受保护片段必须逐字出现在译文中，否则整批拒绝显示，不做修复或部分展示。展示前仍以同一张已持有的原图基线核对目标与内容是否变化（不重新截图），变化即撤除。
- **绘制计数**：HUD 使用四类真实结果计数（已绘制/空间不足/与相邻文字冲突/无可用原文位置），四类之和等于条目总数；无可用原文位置的区域不再丢弃全文。计数只描述本次绘制结果，不是定位精度或覆盖率证据。
- **渲染修正**：原位置绘制改用实际可绘制字形几何（而非把 OCR 框当作可绘制区域），行间隙不再被填满；无可用原文位置的区域仍保留条目与全文，供展开面板读取。该修正同样只有 `swiftc -parse` 证据。


- **验收反馈（2026-10-16）**：展示后内容变化不再自动撤除（仅几何/身份/遮挡类失效保留）；展示后 HUD 收起为可拖动小图标，点击展开；屏障保持 key，Esc 仍关闭。

### 2026-10-20 源语言残留标记（源码已改，未构建未运行）

目标语言为英文（`en`/`en-*`，大小写不敏感）时，已绘制条目若译文仍有超过 30% 的字母是 CJK（汉字/假名/谚文），且该区域捕获原文本身含 CJK 字母，则该区域的调试分类由 T/E/S/V 改为 **R**，子原因 `source-language-residue`（`R` 原义“已规划无译文”保留；图例标签与显式 JSON 导出的 `subreason` 都显示该子原因）。判定不读配置的源语言，`auto` 与固定源语言一致，英文原文永不触发；未保留配对原文的条目（例如没有匹配区域或未绘制）永不判为残留。

这是纯诊断，不是新的绘制、保护或回退策略：计划、绘制矩形、遮罩、保护片段、新鲜度与 HUD 四类计数全部不变（残留区域仍计入已绘制），只撤回“成功”的调试分类；日志无条件追加一行仅含计数的「译文仍含源语言字符：N 个区域」，不含原文或译文。除逐文件 `swiftc -parse` 外未构建、未类型检查、未运行；`tests/DesktopChecks.swift` 新增 `residueChecks()`（阈值边界、`en`/`en-*` 大小写与源语言门控、S/V 改判、R 子原因与标签、非英文目标不触发、计数与日志行不含正文、导出 JSON 往返）尚未执行。
