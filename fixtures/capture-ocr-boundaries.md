# Capture and OCR boundaries

`TargetLocker.lock(app:)` locks the topmost ordinary window of the supplied pre-UI frontmost application by PID and CG window. It refuses this process's own PID (`.ownApp`), a terminated or non-frontmost application, duplicate window IDs (`.ambiguous`), a translucent top window over a lower same-app sibling (`.overlappingWindows`), and a window that intersects no display (`.offscreen`); it never activates anything and has no display or other-window fallback. Capture then adds the remaining gates: `selection == target.effectiveSelection`, target revalidation, full visibility, no other-PID layer-zero occlusion, a desktop-independent single-window filter, `sourceRect` equal to the selected window-local points, shadow exclusion, `scalesToFit` off, and an actual image size within one pixel of the expected size.

Screen Recording is checked before capture: denied or revoked access is `.needsPermission`, distinct from capture errors. A target absent from `SCShareableContent` with exact windowID/PID, on-screen/layer 0/equal frame, an SCK error, or an all-black result is explicitly cannot-capture (possibly system- or app-protected), never no-text, and never proof of protection. Empty OCR alone is `.none`.

Vision runs at `recognitionLevel = .accurate`. A fixed source language selects that language's recognizer plus English; `auto`, or a language without a Vision recognizer, uses Vision's own detection. Language correction is disabled for the built-in terminal bundle IDs. Legacy `kCGWindowSharingState` values are non-authoritative diagnostics only, not refusal, allowance, or user-warning predicates. Accessibility secure-subtree exclusion applies only to AX reads: OCR cannot detect or exclude secure controls, sensitive pixels, or legacy anti-capture intent. Partially black regions may leave other pixels available to OCR; the locked window and selection are the exclusion boundary.

Pi modes are explicit and frozen with the settings. The default `translation.inputMode: "ocr-text"` sends only the locally recognized source text. `"image"` sends the exact cropped pixels of the selected area and requires a model that declares image input; it is not an automatic fallback when OCR fails. `pi-smoke`, `glyph-pi-smoke`, and `terminal-fixture-pi-smoke` may therefore send public fixture text, or the fixture crop in image mode, to the user's configured pi service; pi must be installed and configured separately, and the repository ships no credentials.

OCR capability is reported as `.partial` with visible confidence, background, clipping and provenance warnings. Background is an unverified edge-median bitmap sample, not a native color or font claim. Before presentation the returned baseline signature must survive two samples; after the overlay is presented the monitor is geometry-only (identity, frame, Space, screen, occlusion, frontmost), so content changes no longer withdraw it. No heuristic caret mask is claimed: ScreenCaptureKit excludes the pointer via `showsCursor=false`, while an unproved blinking caret remains part of the pre-display comparison and may cause conservative removal.
