# 产品变更 001：通用桌面翻译、应用插件与定位 OCR

状态：方案经 Opus 复审 **PASS_WITH_NONBLOCKING**，允许开始开发；[报告](../../reviews/opus-plan-review.md)。已部分实现，**未验收**，不是已发布能力；现有探针不代表全部验收门槛通过。2026-10-16 的 pi 截图输入、模型下拉与绘制计数修改只完成源码写入与逐文件 `swiftc -parse`，**未构建、未类型检查、未运行**，不构成新证据。

## 用户目标

把当前 cmux 专用阅读层升级为通用桌面翻译工具，类似截图翻译：识别桌面中的目标软件，优先加载该软件插件；没有插件时使用 OCR，在原文字位置显示译文。再次按快捷键或 Esc 完整恢复显示。

对应请求条目 1、2。终端专用插件见产品变更 002。两项变更共用已有的本机/pi 可选翻译后端和可配置快捷键。

## 范围与行为

1. 目标为当前前台应用活动窗口；默认一键使用锁定窗口完整 CG bounds（window-local `(0,0,w,h)`，包含标题栏，无需 AX/content inset），终端只有已证明聚焦 pane 身份、几何与可靠 inset 时使用该 pane；无法唯一确定 CG bounds 停止，不猜 inset。菜单“区域翻译”拖选、Return确认、Esc取消；仅按(bundleID,windowID)会话记忆，resize/pane变化清除，不扫描后台窗口。
2. 用 bundle identifier、进程标识和窗口标识确定软件和捕获对象；匹配经过注册的插件，显示当前捕获来源。
3. 插件优先；none/unsupported走本机OCR，partial用可靠布局裁剪OCR。error或needsPermission明确显示原因，用户可另选一次OCR，不静默fallback；所有路径先验证唯一目标，身份歧义不能用OCR绕过。
4. OCR 参考 `/Applications/ScreenTextGrab.app` 的截图/区域捕获体验，不依赖它提供未证实的第三方 API，也不复制其代码。
5. 在识别区域的原位置覆盖译文。原应用、文档和终端缓冲区不变，恢复操作只撤除覆盖层。
6. 翻译引擎与捕获插件分离：同一份定位文本可以用本机或用户选择的 pi 模型翻译。
7. 没有必要授权、无法识别文字、失去目标窗口等情况要明确提示，禁止悄悄捕获其他窗口。
8. 本机模式捕获前查询 LanguageAvailability；支持但未安装时不捕获，在“翻译模式、语言与模型…”窗口的“语言包”一行显示当前语言对的状态，并由“准备语言包…”按钮打开独立可激活、无目标绑定的设置窗口。安装完成后用户重新触发，首次下载实际路径纳入验收。

## 共享捕获契约

拟定数据，实现在变更交付时确定语言/API细节：

- `CaptureTarget`：应用 bundle id、PID、窗口 id、窗口边界、显示器、捕获区域。
- `CaptureSnapshot`：唯一快照标识、时间、目标、捕获来源、坐标变换。
- `TextRegion`：稳定区域 id、原文、文字类型/置信度、原坐标矩形、阅读顺序、可选字体/底色估计。
- `LayoutRegion`：父子区域及边界，用于窗口、分屏、正文、代码块、表格。
- 插件声明可用性、应用匹配规则和捕获能力，输出同一契约，不拥有翻译后端和全局快捷键。

坐标必须明确区分屏幕像素、窗口点坐标、显示器缩放与 Vision 的归一化左下角坐标；禁止直接用 OCR bounding box 当作 AppKit frame。

## “精确替换”的可交付定义

精确指**定位和恢复**，不是保证中文与英文长度相同，也不是修改目标应用文本。

- 覆盖矩形与对应原文矩形对齐；不能整窗铺白后把全文重排冒充定位替换。
- 使用原区域布局分组译文，文字不得越界覆盖邻近按钮/文本；有最低可读字号（≥12pt），空间不足需提供用户可见的展开阅读方式，不能静默截断，也不以扩大框体或填补行间隙来伪装容纳。每个译文区域恰好产出一个条目并带如实结果：已绘制、空间不足（仅橙色标记）、与相邻文字冲突（不覆盖也不标记）、无可用原文位置（不绘制）；四类都不丢弃条目，全文始终可经展开面板读取，HUD 按四类计数并只在未全部绘制时提示展开，无任何区域实际绘制时报失败而非成功。
- 保护图标、非文字内容及不在选择区域内的桌面；复杂背景、OCR 低置信度需要明确标记，不保证还原底图。
- 选择、HUD、覆盖与展开用非激活NSPanel并保持fullScreenAuxiliary；全目标窗口透明事件屏障为必选，吞点击/滚轮/手势及非关闭键，Esc/快捷键可用。窗口外操作引起目标切换则撤除，不强行抢回焦点；终端FocusLost实际次数必须记录，不承诺未测为零，非0披露限制。当前不引入event tap；任何新增输入监控/AX权限的event tap路线须更新权限矩阵并经Opus复审。
- 原目标移动、尺寸变化、切换显示器/Space 或消失时，撤除过期覆盖层，不将旧译文贴到新位置；重新捕获由用户触发。
- 展示遮挡只统计其他PID、目标之上的layer 0窗口，排除自身屏障/HUD/overlay；通知/Dock等系统层不导致误撤除。

## 权限与隐私

目标锁定与窗口变化以无需AX的前台PID/CGWindowList唯一窗口及轮询为基线；AX仅已授权或插件所需的增强。OCR与截图失效检测需要屏幕录制；原生revision为可见文本重读哈希，不需要截图。Terminal/iTerm2原生路径、Ghostty脚本焦点路径按目标请求Automation，Info.plist有NSAppleEventsUsageDescription，进程内发送AE。各插件SR/AX/AE/应用设置、请求时机、拒绝needsPermission与显式另选OCR见DESIGN权限矩阵；拒绝、撤销、周期确认均说明用途并停止，不改权限。

截图与原文默认只在内存。OCR 在本机执行；pi 模式默认只把本机识别出的正文发给用户所选 provider，只有用户显式选择截图输入时才把所选区域的完整裁剪作为图像发送。覆盖层、错误和日志不输出私有原文。需测试拒绝授权、撤销授权及敏感区域排除。

敏感排除边界是锁定窗口与选区：ScreenCaptureKit sourceRect只含选区，选区外像素不进入内存；AX跳过AXSecureTextField等安全角色及子树，仅适用于AX读取。捕获前检查屏幕录制权限，缺失/撤销单独报告；SCShareableContent未列出同windowID+PID、onScreen、layer0、相同frame目标、SCK错误或全黑结果均明确报“该窗口无法捕获（可能受系统或应用保护）”，不能报无文字或回退其他窗口/显示器，不将所有错误归因于保护。legacy sharingState/NSWindow.sharingType=.none既不证明保护也不证明安全，不作为允许/拒绝或用户警告，仅可作非权威诊断。没有公开保护/安全像素检测接口；OCR不能识别或排除防截图意图、安全字段与敏感控件，局部黑块的剩余像素仍可能OCR。pi provider在捕获前可见；默认只发送待翻译正文，只有用户显式选择截图模式时才发送所选区域截图（内存 PNG、经 stdin、不落盘、不入日志或错误、不放进进程参数）。所有pi/认证助手/终端CLI通过共享disclaim spawner放弃TCC责任，符号缺失fail closed；只加载内建插件。

### 2026-10-16 pi 输入方式、模型来源与绘制计数（源码已改，未构建未运行）

以下为 2026-10-16 源码级设计，除逐文件 `swiftc -parse` 外未经构建、类型检查或运行验证，不是验收证据，也不改变上文任何未通过门槛。

- **输入方式显式选择**：pi 模式新增 `translation.inputMode`，取值为 `ocr-text`（默认，旧配置无该键时按此解释）或 `image`。截图模式是用户显式选择，不是 OCR 失败时的自动回退或改进，也不存在模式/模型回退；设置界面在选择处显示该模式的发送内容与风险，并在捕获前可见。
- **截图模式的隐私与传输边界**：每次翻译捕获与 OCR 路径相同的精确锁定窗口/选区裁剪，编码为内存 PNG 后经 stdin 作为一条图像内容发送；不写临时文件、不入日志/错误、不放进进程参数、随会话丢弃。因此“只发送正文、不上传截图”只对默认 OCR 文字模式成立，不适用于显式选择的截图模式；截图模式会发送该裁剪内可见的一切，包括模型不需要或用户未预期的内容。
- **模型来源与能力**：模型下拉由 pi 自身 `get_available_models` 填充（只读取该命令，不发起模型请求），显示 `provider/id` 与是否声明图像输入；已保存但当前不可用的模型保持可见并标注，不被静默替换；截图模式只列出声明支持图像输入的模型，并在所选模型不可用或非图像模型时拒绝保存/发送。pi 声明支持图像输入不等于远端部署一定遵守该声明。
- **截图模式的位置证据边界**：位置由模型自报，是相对该裁剪的比例，映射回窗口本地坐标；不是原生或 OCR 验证过的几何，也没有 OCR 校准，因此对模型未识别或未报出的图标、非文字内容与文字没有任何保证，不为其生成译文或位置，也不代表定位精度达标。区域必须落在裁剪内、受保护片段必须逐字出现在译文中，否则整批拒绝显示，不做修复或部分展示。展示前仍以同一张已持有的原图基线核对目标与内容是否变化（不重新截图），变化即撤除。
- **绘制计数**：HUD 使用四类真实结果计数（已绘制/空间不足/与相邻文字冲突/无可用原文位置），四类之和等于条目总数；无可用原文位置的区域不再丢弃全文。计数只描述本次绘制结果，不是定位精度或覆盖率证据。
- **渲染修正**：原位置绘制改用实际可绘制字形几何（而非把 OCR 框当作可绘制区域），行间隙不再被填满；无可用原文位置的区域仍保留条目与全文，供展开面板读取。该修正同样只有 `swiftc -parse` 证据。


- **验收反馈（2026-10-16）**：展示后内容变化不再自动撤除（仅几何/身份/遮挡类失效保留）；展示后 HUD 收起为可拖动小图标，点击展开；屏障保持 key，Esc 仍关闭。

### 2026-10-20 源语言残留标记（源码已改，未构建未运行）

目标语言为英文（`en`/`en-*`，大小写不敏感）时，已绘制条目若译文仍有超过 30% 的字母是 CJK（汉字/假名/谚文），且该区域捕获原文本身含 CJK 字母，则该区域的调试分类由 T/E/S/V 改为 **R**，子原因 `source-language-residue`（`R` 原义“已规划无译文”保留；图例标签与显式 JSON 导出的 `subreason` 都显示该子原因）。判定不读配置的源语言，`auto` 与固定源语言一致，英文原文永不触发；未保留配对原文的条目（例如没有匹配区域或未绘制）永不判为残留。
